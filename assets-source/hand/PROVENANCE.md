## Quest neutral calibration

On November 5, 2026, Paul authorized a live open-hand capture from the attached Quest. Each side's reference averages 12 stable frames from that capture. `tests/fixtures/quest-neutral-hands.json` stores the mean joint transforms normalized to the wrist, without room coordinates or device identifiers. `src/xr/hand-neutral-reference.json` stores the derived palm-relative joint quaternions. These are owner-specific neutral references, not a change to the Blender mesh, rig or editing groups.

For each tracked bone, the renderer computes the current palm-relative rotation times the inverse neutral rotation, applies that delta to the authored rest orientation, and removes the current parent world rotation. Parent-first updates prevent thumb base motion from bending the next thumb joints a second time. Bind translations and scales remain fixed. This uses the joint orientations defined by the [WebXR Hand Input specification](https://immersive-web.github.io/webxr-hand-input/), retaining twist that a position-only segment direction cannot represent.

Regression checks compare the rendered neutral mesh with the authored Open mesh for both hands and verify rigid thumb base motion without extra child bends. The calibrated neutral vertex error is below 0.01 mm in those fixtures. Physical Quest appearance and pinch comfort remain owner acceptance.

The visible thumb starts at the palm-edge MCP joint, not the anatomical metacarpal joint inside the palm. Both `thumb_01` and `thumb_02` therefore use the tracked `thumb-phalanx-proximal` rotation and its matching neutral reference. Together they form the 39.51 mm proximal section. `thumb_03` uses `thumb-phalanx-distal`, retaining the tip hinge at x=110 mm and a 20.01 mm distal section. Independent Blender inspection confirmed the root at x=70.67 mm and strong thumb-root weights at the palm junction, so the mesh, weights and rig remain unchanged. Regressions move the proximal joint while holding the metacarpal still, reproducing the previous halfway bend on both hands before verifying the corrected palm-edge hinge.

## Initial rig history

The hand was modeled by Paul Robello and supplied in the open Blender scene. The snapshot `original-hand.blend` was saved from that live scene before rigging. It preserves the user's editable edge mesh, Skin and Subdivision modifiers, material, and scene data. SHA-256: `e9ab1bd430680efac0269d759a541b93d5966043834e4caf4f2a7f6964d387fe`.

`rig_hand.py` derives the orange skinned mesh and armature from that snapshot using Blender 5.2.2. For regeneration, run `blender original-hand.blend --background --python-exit-code 1 --python rig_hand.py --python animate_hand.py` from this directory. The script retains the original object hidden, bakes its evaluated surface, constructs the skeleton and weights, and exports `authored-hand.staged.glb` and `rig-metadata.json`. The editable result is in `rigged-hand.blend`. The user's open source file was also saved with the rig, with the original object retained and hidden.
