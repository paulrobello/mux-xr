# Workspace guide

See the [README](../README.md) to start the app and the [host setup guide](HOST-SETUP.md) to connect a streamer or enable local host features.

## Panes and terminal controls

Select a pane to attach it, then explicitly select its panel to target input. Commands and Keyboard follow explicit pane selections, including while the drawer is open. The target caption identifies the pane receiving input. Only the active input pane is highlighted. Enable **Gaze input** to let a short dwell choose the keyboard target. It is off by default and keeps the last target while you look at the keyboard.

Each desktop and XR terminal has **Close view** and **Disconnect / Reconnect** controls. Each also has **Bring here**, which moves that pane level in front of you at the saved focus distance, turned to face you, and saves the new placement. Unlike Focus it does not fade the other panes or restore anything later. Close view removes the virtual panel while its mux pane and shell continue running. Reopen it through Panes. Disconnect retains the panel, last image and placement, stops retries and rejects input. Reconnect attaches to the same pane without replaying input. Network interruptions still retry automatically. A malformed or incompatible stream shows a bounded error and waits for explicit Reconnect. Incoming frames accept the core's bounded 9 MiB payload size, including large initial scrollback seeds.

Connected viewers retry dropped connections with capped backoff until detached. Unsent input is rejected and is never replayed after reconnect. Existing remote grid dimensions are adopted on attach, and the XR window follows server-confirmed rows/columns without moving or rescaling its root.

### Create terminals

Each session in the browser workspace tree has a **New terminal** button. In XR, open Panes, choose a workspace and then a session, and select **New terminal** in the right-hand column below Up. Either control asks the streamer for one new default-shell window in that session (core `pane_create_request`, available since core 0.77.0). The streamer starts the default shell. With core 0.81.0, the app names the new window `xr`. The new pane is attached once the hierarchy lists it, and in XR the Panes selector closes so the new view is in front of you. Existing panes and views are not replaced, resized or sent input.

Creation requires a writable streamer with `--allow-pane-create`. Core 0.81.0 reports capability at pane attach, so the app can disable the control immediately. Older streamers omit the field and the control learns from the first refusal. A refusal because creation is disabled, the connection is read-only, or mux support is unavailable disables creation for that connection.

The app never retries a creation request automatically. If the reply is ambiguous or missing, it refreshes the hierarchy while the control is locked. A newly observed pane is reported without opening it. A timeout accepts late replies for 10 seconds and otherwise leaves creation disabled until reconnect. A daemon failure allows a new attempt after reconciliation.

### Mux hierarchy navigation

The XR **Panes** surface presents the workspace/session/window/pane hierarchy as real 3D geometry. The default **Helix Navigator** arranges nodes around a compact helix. **Spatial Docks** places the same hierarchy in spatial dock groups. Choose **Hierarchy style** in browser Workspace settings, or use the native **Settings → Display → Mux tree** control. The choice is saved locally and stays synchronized between browser and native settings.

The initial view shows the current workspace and its sessions. Navigation centers the current parent and shows one spherical child level at a time, hiding unrelated siblings. Click a node to expand it. Ancestors remain available as breadcrumbs, and Home, Up and paging retain parent context. Selecting a pane leaf opens the existing pane view and closes the navigator, without changing the remote process. Press B to close the navigator without entering Focus.

With tracked hands, bring the index-thumb pinch point within about 8 cm of a node to ring it in blue. Pinch and open on it to select it, exactly like a ray click. A pinch that closed away from the node never selects. While either hand is near a node both lasers turn off, as they do near the keyboard.

Grab a pane node, by gripping on it with a controller ray or making the middle-finger-to-thumb grab with a hand at it, to pull that pane out. A ghost panel follows your hand, growing to the size the terminal will open at, and releasing it at least 10 cm away opens the pane there, facing you, and closes the navigator. A pane already on screen moves to the new spot instead, ending Focus first if it is focused. A shorter pull, or one where hand tracking drops, cancels. Grabbing any other node moves the whole navigator: one- and two-controller grip gestures use the same manipulation behavior as other XR surfaces, and its transform and navigation state survive style changes. While it is open, terminal view roots are temporarily hidden. Closing or switching away restores their original visibility.

The desktop DOM hierarchy remains the accessible fallback. The bundled XR labels use crisp local text and the hierarchy uses muted teal and ivory node bodies, amber branch/attached states and dim connectors. Children contract into the current parent and expand around the newly selected parent. Immediate child shapes and the gold rings on attached panes rotate slowly while labels remain stable. Circular Home, Up and paging controls catch rays across the whole circle, including its center. Breadcrumbs remain available, and Spatial Docks has no translucent base.

### Agent roster

When the streamer runs against a par-mux daemon it pushes the agent roster (core `AgentRoster` on connect, `AgentStateChanged` as states change) on the hierarchy socket. The browser sidebar lists it under **Agents**, above the workspace tree. The state glyph and word are coloured by state: question and blocked in amber, working in cyan, done in green. The app redraws only when a shown token changes, and XR coalesces bursts of state changes into one rebuild.

Each entry is configurable the same way as par-mux's `[client] agent-rows`: a list of lines, each a list of tokens joined by ` · `, where a token with nothing to show drops out. Choose a layout under **Workspace settings → Agent roster → Rows**. The default **Full** layout shows `state_icon, state, agent, title / workspace, project, pane / message`. The par-mux presets **default**, **compact**, **detailed** and **verbose** match par-mux token for token. **Custom** takes your own rows, with lines separated by `/` and tokens by commas, for example `state_icon, agent / project, pane`. Unknown tokens are skipped and named in the hint. The tokens are par-mux's `state_icon`, `state`, `workspace`, `project`, `message` (the blocked or question reason), `agent` and `pane`, plus `title`, `session`, `window`, `source` (hook, scrape or self), `activity` and `input` (time since the last output and since the last human keystroke), `viewers` and `cpu`. The streamer refreshes `activity`, `input`, `viewers` and `cpu` only on a full roster fetch (connect, or a host-telemetry change), so they are as of that fetch. The browser counts the ages up between fetches, and XR leaves time tokens out.

The button on the **Agents** heading cycles the order: **pane** (the default, so rows never move under the pointer), **grouped** (par-mux's workspace groups with the most urgent state first) and **priority** (question, blocked, done, working, idle). When an update would reorder the list while the pointer is over it, the reorder waits until the pointer leaves. Updates that keep the order apply at once. XR nodes always stay in pane order so nothing moves under a ray. The layout and order persist with the other workspace settings. Click a row to attach and focus that pane, exactly like choosing it in the tree. In XR, the Panes hierarchy has an **Agents** group at Home, and an **Agents** shortcut next to Up on deeper levels that turns coral when an agent needs attention. Its pane nodes are coloured by state and open the pane like any pane node. The nodes follow the browser layout: each label shows the layout's first line, with the state word in place of the glyph. Its help text joins every line. Rows only list panes the hierarchy currently has.

Core 0.81.0 improves roster updates for self-reported state, blocked reasons, presence stamps and removed panes. See the [core review](core-0.81-review.md) for the compatibility boundary.

## Spatial controls

Mouse clicks in 3D preview and controller triggers in VR use the same actions, with one input presenter per mode. Browser Keyboard/Commands use the compact DOM drawer. Immersive VR uses spatial controls only. Hover with the mouse or aim a controller ray at a non-obvious control to see its explanation. DOM icon and modifier buttons also have browser hover titles.

| Radial item | Owns |
| --- | --- |
| Keyboard | Keys, modifier locks, target readout, Gaze input and Backing. |
| Commands | Global/workspace commands and their editor. |
| Panes | Hierarchy browsing and opening/selecting pane views. |
| Layout | Row, Grid, Arc, Sphere, Closer/Farther and recovery. |
| Warp | Right-stick left/right adjusts curvature and up/down adjusts opacity. A saves both, B cancels. |
| Widgets | Add, show, or hide [widgets](#widgets), including pictures and dictated sticky notes. |
| Settings | Display, World and Selected terminal pages, Keyborb mode and UI sounds. |
| Focus | Temporarily bring the aimed or selected pane forward. |

Press A to open the selected tinted ring. Its center expands first, eight options emerge as a stack, then move around the circle into their final positions. The menu opens in about 640 ms. Moving targets cannot be activated or grabbed. Point and trigger to choose Keyboard, Commands, Panes, Layout, Warp, Widgets, Settings or Focus (which toggles Focus on the pane aimed at when the menu opened). Center Cancel or A closes it. B remains Focus outside Warp editing. Scrolling and underlying terminal activation are blocked while the menu is visible.

### Grab, move, and recover

Every XR UI surface (pane, keyboard, commands, hierarchy and workspace HUD) is a grabbable root. Grip one controller to move and rotate it: thumbstick X yaws and Y pitches, without Y translation. Grip plus trigger rolls around the controller laser axis with thumbstick X and pushes or pulls along it with thumbstick Y. Grip the same surface with both controllers to resize by spreading or bringing hands together, rotate by changing hand direction, roll it by turning both wrists or controllers the same way about the line between them (past a dead zone of 8° for controllers and 15° for hands), and move it with the hand midpoint. Hands have no thumbstick, so a hand ray grab of a surface more than 0.5 m away reels it with your reach: pull your wrist toward your body to bring it closer, or extend your arm to push it away (0.3 m to 6 m, with a 5 cm dead zone). Walking carries it at the same distance, and sweeping your arm sideways leaves its depth alone. A terminal pane held this way stays level and keeps turning to face you, so rolling your wrist neither tilts its text nor swings it around your hand. Touch grabs move 1:1.

The 3D preview toolbar always exposes **Smaller panel**, **Larger panel** and **Reset layout**, independently of pane geometry. Preview enlargement is bounded to keep the panel and attached controls inside the viewport. In VR, physical resizing uses grip gestures. Layout also offers workspace recovery. Hover help uses compact labels that scale with viewing distance after a 700 ms dwell, shows actions only and is hidden while gripping. With hands, radial Layout → **Reset layout** (or **Closer**) brings far panes back. If UI space is lost, release all grips and hold both thumbstick clicks for one second to recenter every pane, the HUD and input surfaces near the current headset position and reset physical scale. This recovery does not resize the PTY. Surface scale and text zoom leave terminal rows and columns unchanged.

**UI sounds**, on by default, play short synthesized clicks in XR: a click for each control or key press, rising and falling tones when a grab starts and ends, a quiet tick for each scroll-strip line batch, a two-note chime when a held modifier locks, a double beep when a press-twice control arms, a low buzz when a paste fails and a sweep for the both-stick recenter. Controllers also get a short haptic pulse on the same events. Tracked hands get sound only. Turn both off with **UI sounds** in browser Settings or XR Settings. The setting is saved and synchronized between them.

### Hand input

VR and passthrough request optional WebXR hand tracking. On a supporting headset, put the controllers down and enable the headset's hand tracking. Controllers remain available when hand tracking is unavailable.

Point the headset-provided hand ray and pinch **index finger to thumb** to select controls, type keys, run a saved command or select a pane. Touch the watch on your right wrist to open the same radial menu available through right controller A. Keyboard modifiers retain their tap-once and hold-to-lock behavior, and explicit pane selection retargets the keyboard and commands.

**Keyborb** is an alternate spatial keyboard with translucent spherical keys and floating letters and symbols. Browser Workspace Settings and native XR Settings share a saved **Off / On / Auto** preference. **Auto**, the default, uses Keyborb when hand-tracking input sources are active and the standard keyboard with controllers. **On** always uses Keyborb, and **Off** always uses the standard keyboard. Keyborb retains the same 68-key layout, modifiers, curvature, target and placement. Point and press the controller trigger or pinch index to thumb to type. When speech is available, a **Mic** orb at the top of the Keyborb starts dictation with the same pinch and release, reads **Stop** while listening, and the transcript then edits with the orbs: Enter inserts it and Esc cancels. The Keyborb panel has no separate **Dictation** button, since the Mic orb replaces it. Hand hover and contact alone never send a Keyborb key.

Bring your index finger or thumb near Keyborb to lift the orb closest to the midpoint between the rendered thumb and index fingertips toward your hand by its full diameter. Both lasers and their distant selection and grab actions turn off when either hand is near a keyboard. Closing a relaxed index-thumb pinch highlights the raised orb, and opening the pinch types it and flashes the orb mint green. Modifier keys still act when the pinch closes, so holding one locks it. While the pinch is closed, moving most of an orb's width onto a neighbor hands the target over without typing the first orb, and a brief tracking dropout under 100 ms keeps the held key. Open your fingers before pinching again. The headset's native pinch is also accepted when the custom opening threshold was not reached. Each hand can target a different orb, and hovering or touching still never types. Farther away, the hand ray remains available with the same forgiving pinch selection.

With the standard keyboard (**Keyborb: Off**, or Auto with controllers), bring your hand within about 14 cm of the keyboard to hide both lasers and type by pressing keys with your index fingertip. Withdraw before pressing again. Modifier taps and holds work with contact, including on curved keyboards. Both lasers return when both hands leave the keyboard proximity area. Direct contact grabs remain available.

On both keyboards and the command editor, the panel controls (Close, Backing, Gaze input, the curve − and +, Paste, Paste host, Copy to host, Dictation and the dictation review buttons, quick-strip commands and the editor buttons) are raised 3D buttons. Poke one with an index fingertip, tracked or controller-held, while the lasers are off, or point and press when no hand is near. A poke presses once per approach, clicks and pulses like a ray press, and keeps press-twice confirms. Keyborb orbs still type only by pinch.

Touch a surface and grip the controller, or pinch **middle finger to thumb** with a tracked hand, to grab the object you touch. Distant surfaces still support aiming and gripping. Move or rotate your hand to manipulate the whole pane, keyboard, command panel, hierarchy, HUD or clock. In the hierarchy, grabbing a pane node pulls that pane out instead (see Mux hierarchy navigation). Grab the same surface with both hands and change their separation to resize, or move their midpoint to translate. Releasing one hand continues with the other without a jump. Grabbing suppresses typing and terminal mouse input.

Hands open curvature presets and Curve less / Curve more through **Menu → Warp**. The pane previews each press live. **Done** saves the curve, and **Cancel**, closing the panel or switching panels restores the curve from before the panel opened. Controllers retain direct thumbstick Warp editing. **Menu → Focus** toggles Focus on the selected pane, standing in for the controller B button.

Tracked hands use the authored Blender hand, with a 13-bone rig for its palm, three fingers and thumb. The editable source, rig and pose actions live in [assets-source/hand](../assets-source/hand). A procedural hand remains available while the asset loads or if loading fails. Elastic arms curve from the wrists to separate anchors 20 cm left/right, 18 cm below and 4 cm forward of the camera. They stretch with the tracked wrists and sag slightly, with a small amount of smoothing in the middle of the curve. The rendered hand preserves its authored bone lengths and cross-sections at the authored physical size. Open hands retain the authored pose. Closing adds bounded palm cupping and thumb-base movement. Separate left/right open-hand references captured on Quest calibrate tracked joint rotations to the authored resting pose. The tracked wrist drives the hand root pose. The thumb moves from its visible palm junction, with a separate bend near the tip. Raw tracked fingertips still drive input, while the rendered skin is stylized and does not promise exact tracked-tip correspondence. The slim source digits are about 23–27 mm across. The hands and arms do not catch rays or send input.

Controllers show the same hands. Trigger pressure curls the index finger, grip pressure curls the lower two fingers, and the face buttons animate the thumb. A rounded wrist joint overlaps the arm and hand to keep their connection closed as they rotate. The right wrist carries a watch showing device-local **12-hour time with AM/PM**, updated each minute: touch its case or band with any part of the left hand, or point at it from farther away and press the left controller trigger. The left ray turns off near the watch. A touch press clicks once and pulses the left controller, like a pointer press. Withdraw the hand before touching again. Right controller A still opens the menu and left X opens Panes by default. Remap right A, right B, left X and left Y to Menu, Panes, Focus, Keyboard, Commands, Layout, Warp, Widgets, Settings or Nothing in XR Settings → Controller buttons or browser Settings → Controller buttons. While warping a pane, right A saves and right B cancels whatever they are mapped to. The left menu button does nothing: on a Quest 3 its press never reaches the page.

Tracking loss hides the hand and arm, releases manipulation and cancels in-flight input. Open both pinches after tracking returns before starting another gesture. Desktop/browser hand fixtures verify software behavior only. Gesture comfort, occlusion recovery and typing precision still need real Quest 3 hand testing.

### Keyboard and dictation

A paired Bluetooth or USB keyboard types into the selected connected terminal, on the page and in immersive XR, unless focus is in a text field or the in-scene command editor is open. On the 2D page the text-field rule applies, so keys typed into inputs stay there. In immersive XR, keys go to the selected terminal. A brief indicator shows each key received (marked "not sent" when filtered), which also proves whether Quest Browser delivers keys during a session. Alt and Option act as Meta (an Esc prefix), so Option-composed characters on non-US macOS layouts are not typed. Cmd shortcuts stay with the browser.

The desktop and XR keyboards use the same familiar key positions, with Enter at the right of the home row, wide Shift/Backspace/Space keys, and a separate inverted-T arrow cluster. Right-controller **A** opens or closes the tinted radial action menu. Choose Keyboard to toggle the keyboard. It preserves the keyboard pose and active target, and ignores presses made during a grip. **B** continues to toggle terminal Focus mode. A temporarily hidden keyboard retains its locks for the same target, while pane/context changes and XR exit clear them.

The virtual keyboard has terminal keys above the arrows, including Insert, Delete, Home, End, Page Up and Page Down. Shift, Ctrl and Alt send modified xterm sequences where applicable. A short modifier tap applies to one key. Hold a modifier for about 550 ms to lock it until tapped again.

With hand tracking and no controllers, the keyboard and command editor open about 0.45 m ahead and 0.4 m below your eyes, tilted toward you by 30°. A saved position takes priority.

Keyboard settings include a saved **Keyboard curvature** range from 0° to 100°. Curved backing and key geometry preserve ray picking and the shared keyboard-root grip behavior. Keyboard Backing remains an independent toggle.

Keyboard dictation prefers local Whisper on this Mac when the browser supports microphone recording. Choose **Dictate**, speak, choose **Stop dictation**, wait for transcription, review the editable text (in XR, the box headed **Transcript**), then choose **Insert text**. Insertion sends text without Enter and stays locked to the connected pane captured at start. **Clear** empties the reviewed draft while keeping the editor and selected pane active. It is available after recording/transcription ends. Cancel, retargeting, close and disposal stop capture or transcription and release the microphone. See [local Whisper dictation](HOST-SETUP.md#local-whisper-dictation) for setup and limits.

### Scrolling and terminal mouse input

Each terminal has a thin scroll strip. Pinch it or hold the trigger and drag down to reveal older output. **Scroll strip** in browser Settings or XR Settings → Display sets which edge carries it.

Point at a terminal and use either controller's stick up/down to scroll. Both grips must be released, the radial must be closed, and other panels must be closed except Keyboard. No trigger is needed. Ordinary shells use local scrollback. Mouse-aware TUIs receive raw SGR wheel reports. Browser wheel scrolling works in both flat terminals and the 3D preview.

For TUIs that enable mouse tracking, point at the terminal and press the controller trigger for a left click. Hold the trigger and move the ray to drag, then release it. Movement is sent only over the captured pane, and the release stays with that pane. Grip suppresses mouse input and safely ends an existing drag before window manipulation. Desktop terminal canvases also support pointer click/drag. Mouse coordinates follow the remote grid, physical transforms and local text zoom. Disabled tracking, read-only and disconnected streams reject mouse input.

In XR, trigger-drag over ordinary terminal text selects it locally. Releasing a completed drag copies the exact text, clears the highlight immediately and shows a copy toast. Choose **Keyboard → Paste** to insert it into the selected connected terminal without Enter. If browser clipboard access is blocked, the copy stays available inside Mux XR and the toast says so. Paste also reads text copied outside the app when the browser permits it. A click without a drag only selects the pane. An XR press only becomes a drag once the hit has moved at least 2 cells and 1.5° of ray angle from where it started, so a shaky pinch or trigger stays a click. The same dead zone applies to XR mouse drags in TUIs, while desktop mouse drags stay exact. Grip cancels an active text drag without copying. Gripping or moving UI after a completed drag preserves a pending clipboard write. Mouse-enabled TUIs keep their mouse behavior. Local text copy also works from a disconnected pane's retained view and never sends clipboard commands to par-mux.

### Focus, warp, and terminal settings

Press **B on the right controller** while pointing at a terminal to enter Focus mode. With no terminal under the ray, it uses the active pane. The pane moves in front of your current view at the saved focus distance (default 1.5 m) and focus warp, while the other terminals fade out. Its placement stays fixed as your head moves, and the keyboard and HUD remain available. Press B again to restore its exact original position, rotation, scale and normal curvature and fade the other terminals back in. While Focus is active the pane's **Bring here** button reads **Keep here**: press it to end Focus but leave the pane where it is now (with its normal curvature) and save that placement. B is ignored while either grip is held. Selecting a different pane, applying an arrangement, recentering or leaving XR safely ends Focus mode. This never resizes the terminal grid or stops its process.

Choose radial **Warp** to edit the pane aimed at when A opened the menu, falling back to the active pane. Right-stick left/right previews curvature from flat to 100°. Up raises glass opacity and down lowers it (10–100%). Move the stick diagonally to preview both together. A saves and exits, while B restores both original values. Grip pauses editing and retains normal manipulation. Gaze routing, scrolling and trigger input pause during Warp. The next separate A press opens the radial again. Browser Workspace Settings has the same selected-pane slider. Curvature is saved per server/pane, preserves the remote grid and mouse UV mapping, and is included in layout spacing/floor checks.

Settings → Selected terminal includes saved per-pane glass opacity controls from 10–100%. Browser Workspace Settings has the same slider. The dark backing becomes translucent while normal bright text stays opaque. The frame is a separate hollow bezel, so adjusting opacity does not abruptly remove the border or require repeated texture uploads. Warp panel edits are saved per pane only when used: opening the Warp panel and pressing **Done** without touching a preset or the stick saves nothing, so the pane keeps following the new-window defaults. Pressing a preset or moving the stick before **Done** saves even when the final curve equals the starting one, which pins that curve deliberately. Controller stick editing saves only the values that differ when you press A.

Settings → Display also owns new-window opacity and Focus preferences. New terminal views use the saved default glass opacity (10–100%, initially 100%) unless that pane has a saved override. Changing the default leaves open views and panes with saved opacity or warp unchanged: use **Reset to defaults** (Settings → Selected terminal, or the per-pane controls in browser Workspace Settings) to clear a pane's saved opacity and warp so it follows the new-window defaults again. Reset applies the defaults at once, does not save them, and replaces the start value of an open Warp panel edit, so Cancel returns to the reset curve and Done saves from it. During Focus the focus warp stays until Focus ends, then the pane returns to the reset warp. Opacity changes and resets on a faded pane during Focus are kept when the fade ends. Focus distance is saved from 0.5–5 m, defaulting to 1.5 m. Focus warp is saved from 0–100°, defaulting to flat. Both focus settings apply to any focused window and update an active focus immediately. Exiting focus restores its original placement, scale and per-pane curvature.

Display owns color modes and Filtering, including independent Sharper gaze. World owns the background selector and VR/passthrough. From a regular VR session, selecting passthrough or Desk Window prepares a named browser entry button for a fresh press. In an alpha-blended session, the World controls switch the view in place. Selected terminal owns grid dimensions, text zoom and per-pane glass opacity. Gaze input appears only on Keyboard. The HUD shows active-pane/connection status, FPS, notices, updates and Exit. HUD **Exit** and Layout → **Reset layout** ask for a second press within about 3 seconds: the first press turns the button amber, relabels it **Exit?** or **Reset?** and plays the armed cue, and any other control or the timeout disarms it. The both-stick recenter hold needs no second press. The ray's hit cursor grows with distance so it always covers about half a degree of view, and with tracked hands it swells and brightens as the index-thumb pinch closes. Terminal views retain title/status, Disconnect/Reconnect and Close view. Typing keys and local text-size buttons no longer repeat on every terminal.

Terminal grid size is changed only from the selected pane in browser Workspace Settings with numeric columns/rows and Apply, or from radial Settings → Selected terminal. Native presets are 80x24, 100x30, 120x36 and 160x48, with ±1 and ±10 draft controls plus Apply. Columns and rows are bounded to 2..300 and 2..150. The controls are disabled while disconnected, and only an explicit Apply sends a resize. Actual dimensions come back from the server as read-only state. Terminal colors are a saved global preference with Comfortable (default), Original and Monochrome modes. The native keyboard uses self-hosted OFL Noto Sans and Symbols 2 through Troika SDF 0.52.5. Unsupported visual glyphs render as `?` while retaining the original title. Keyboard Backing is a saved browser/native-header toggle: off leaves key buttons visible, while the logical grabbable plane remains and can occlude gaze so the input target is retained. The native FPS HUD is an actual frame counter updated about every 500 ms, not a capacity benchmark.

Terminal windows scale from 0.3× to 1.8×.

### Automatic terminal detail

In XR, the pane under your head-directed gaze always uses full raster quality, even with Gaze input off. Nearby terminals remain full quality. More distant terminals use half or quarter raster resolution and reduced update rates, with immediate restoration when looked at. This changes rendering only: keyboard targeting, selection highlights, terminal grids and UI label sharpness stay independent. Hidden focus-mode terminals continue receiving and parsing output. Desktop terminals return to full quality.

Terminal filtering is saved in Workspace Settings and radial Settings → Display → Filtering. Choose Nearest, Linear, Mipmap crisp or Mipmap smooth, plus anisotropy Off/2×/4×/8×/16× (capped by the GPU). Mipmap smooth with 4× anisotropy is the base default. Sharper gaze is on by default: the head-gazed pane uses full raster quality and base-level linear sampling to favor clarity without reuploading textures, independently of Gaze input. Turn it off to keep the selected base filter on every pane. Physical headset clarity remains an owner recheck.

Filtering shows anisotropy only for mipmap modes and hides values beyond the device cap. Sharper gaze has a saved maximum distance, default 3 m, adjustable in browser settings or native Filtering. It uses physical distance and remains independent of Gaze input. Anisotropy primarily affects oblique minification. Higher values can look alike front-on, and base-level sharper gaze bypasses mip smoothing.

See the [measured terminal LOD comparison](performance/terminal-lod-2026-11-02.md) for the workload, limits and results.

## Quick command setup

In XR, open **Commands → New command**. Select **Name** or **Command**, type with the virtual keys, choose **Global** or **Workspace** scope, whether running should append **Enter**, and whether to **Confirm before running**, then **Save**. Saving stores the command on this device without running it. Run a saved command explicitly from the Commands menu. The browser drawer provides label/text fields, the same toggles and Save for the same command store. Selecting a saved command in the drawer loads it into the fields for editing.

Commands are stored per server, identified by host and port (the scheme's default port when none is given), so `https://host` and `https://host:443` share one list. Lists saved under an earlier endpoint spelling are merged into the normalized server on first load.

The XR Commands panel has a **Run / Pin / Edit / Remove** tool row. With Run selected, a command runs when chosen. Pin toggles a pinned command (cyan border). Edit opens the command in the editor. Remove arms the button and needs a second select within about 3 seconds. Remove stays selected after a removal, so the command that moves into the slot is not run by the next select. Pinned commands are listed first, then the most recently run. Up to four commands also appear as a quick strip above the keyboard: the pinned ones, or the most-run ones when none are pinned. Run counts and last-run times are kept per server on this device.

A command flagged **Confirm before running** turns amber and reads **Run <label>?** in XR on first select, and shows the command text on a line below the commands, with control characters drawn as symbols such as ␛ and ⏎. It runs only on a second select between 350 ms and about 3 seconds later, so a quick double-click cannot arm and run it at once. The same timing applies to Remove. Retargeting, switching mode or closing input disarms it. In the browser it asks with a confirmation dialog naming the target pane and showing the command text, truncated to 120 characters.

Put `{{}}` in a command to make it a template. Running it sends only the text before `{{}}`, never Enter, then opens the XR keyboard with a **Then type:** hint showing the rest. The remainder is not sent for you. A single `{}`, as in `find . -exec rm {} +` or `xargs -I{}`, is sent literally. Multi-line command text is sent as one paste where the terminal supports it, otherwise as typed text.

The browser drawer's **Export** downloads this server's commands as `mux-xr-quick-commands.json`, and **Import** merges such a file: commands with a matching id are replaced by the imported copy without asking, so importing an older export overwrites newer edits to those commands. New ones are added. Invalid entries, entries with an empty id or text, and repeated ids after the first are skipped, and the result is reported.

To share read-only commands with every viewer, publish a file in the same format with `make publish-commands FILE=path/to/commands.json`. It validates the file, failing on an empty id or text and on ids that repeat once prefixed with `shared:`, and copies it to `.local/quick-commands.json` (gitignored) and `dist/quick-commands.json`. Later builds copy `.local/quick-commands.json` into `dist/` again. The app loads `/quick-commands.json` at startup. Shared commands appear in a **Shared** group in the drawer and as **Shared · <label>** in XR. They can run but cannot be pinned, edited, moved or removed, and a `pinned` flag in the shared file is ignored. Saving while one is selected in the drawer creates a local copy.

## Spatial arrangements

Use **Workspace settings → 3D arrangement → Apply arrangement** in the browser, or **Layout** in the XR radial menu. Choose **Row**, **Grid**, **Arc** or **Sphere**. Browser Apply opens the 3D preview. Sphere distributes panels over the front of a spherical surface, curving horizontally and vertically as more terminals are attached, with every panel facing the viewer.

Presets apply to currently attached terminals around your current position and heading. They preserve each panel's physical size, text zoom, input target and remote grid. You can continue grabbing, rotating and scaling afterward. Opening another terminal does not reset existing panels. The last chosen preset is saved locally, but applying it remains explicit. Named saved layouts and animated restoration remain roadmap work.

Arrangement spacing measures each window's current grid geometry, title and controls, plus its manual physical scale. Layouts center those complete bounds and increase distance when viewer-facing windows would visually overlap. Physical scale, text zoom, input target and remote grids are preserved. Controller rays extend to reach arranged windows beyond the default ray length. Creating a new terminal through the viewer requires the pending opt-in core API, tracked by [the upstream card](https://board.example.test/board?card=01a1991e1e20727d8ff8a32afc0b212f). Existing default-workspace panes can already be attached.

In **Layout** or browser Workspace settings, use **Closer** and **Farther** to move all terminal panels together. Panel size, rotation, text zoom and terminal grids stay unchanged. Closer stops before the nearest panel enters the viewing space.

The HUD pose and user-placed keyboard pose save on final grip release and XR exit. Saved poses use the workspace reference space, with older viewer-relative poses migrated on load. Both-stick recovery clears those saved poses while retaining commands and other preferences. Widget presence, position, rotation and scale persist locally, including desktop preview and XR reload. Closing a widget removes its saved entry.

Open terminal views, the selected pane, and each saved 3D pose are stored per streamer. Reload resolves them against the current hierarchy and shows a dismissible toast for unavailable panes. Explicitly closing every view saves an empty workspace. Focus-mode placement is temporary and is excluded from the saved layout unless you press **Keep here**. Restoration sends no commands, resize or pane-create request.

## Widgets

Open **Widgets** from the radial menu. See [optional host routes](HOST-SETUP.md#optional-host-routes) for the widgets that need the companion service.

### Clocks

Add a local-time digital or analog 3D clock from **Widgets**. Grip either clock to move, rotate, push/pull or scale it like other UI. Its × closes only that clock.

### Agent board

**Agent board** adds a dark panel at 0.8 scale between the clocks and the HUD that lists every par-mux roster agent: a state colour dot (coral needs attention, cyan working, ivory idle, green done), the state, agent and pane title, an amber **stalled** chip and the age of the last activity. Six rows show at once, first in pane order. Each agent then keeps its row, so a state change never moves a row under the pointer. When more agents report, the ones that need attention or are stalled claim the six slots first: a newcomer takes the row of the agent it displaces, and a **+N more** line counts the rest. A row moves up only when an agent above it leaves with no newcomer to take its place, and the board reads **No agents reporting** without a roster. Rows refresh on every roster change, and ages tick at most once a second. Like the roster's `activity` token, the age is as of the streamer's last full roster fetch, so after a live state change it can read older than the real activity. Point and trigger, or pinch, on a row to select that pane through the same path as the Panes navigator's Agents group. A row whose pane has closed shows a notice instead. Grip anywhere on the board, rows included, to move it. Its × closes it.

### Timer

**Timer** is a 0.27 m panel centred in the gap between the two clocks at their height. A top button toggles Countdown and Stopwatch, Start/Pause/Resume and Reset run the active mode, and the 1m, 5m, 15m and 25m presets (countdown only) set the length and return to idle. A preset is ignored while the countdown runs, so pause first. Stopwatch mode drops the presets and gives the display the freed space. Point and trigger, or pinch, to press. Countdown and stopwatch keep separate state, so a countdown keeps running while the stopwatch is shown. A countdown that ends under the stopwatch shows a small amber **Countdown done** badge above the time and flashes when you switch back. When a countdown reaches zero the face reads **Done** and pulses amber for five seconds, then holds a dim amber tint until Reset or Restart. Time comes from the wall clock passed to each frame, so dropped frames never drift it, and the face text re-renders at most once per displayed second. Grip anywhere on the panel to move it and use × to close it.

### Bell feed

**Bell feed** adds a dark panel at 0.8 scale to the right of the analog clock, turned to face you, that lists recent pane bells and background notices, newest first. Each row has an amber **bell** or grey **note** tag, the pane title (or the notice text, clipped, with the full text on hover) and a relative age that ticks at most once a second. Six rows show at once, with a **+N more** line for the rest, and the header counts pending bells only. A pane has at most one bell row, which follows the pane's renames. Notices reach the feed only when they were raised outside your current action: streamer and connection errors, saved views missing on restore, and blocked automatic XR entry. Feedback to a press (paste, warp, a pane that is no longer open) and storage failures stay on the HUD. A repeated notice moves to the top instead of adding a row, notice rows disappear after 10 minutes, and the feed keeps at most 24 bells and, separately, 8 notices, so notices never push out a pending bell. Point and trigger, or pinch, on a bell row to select that pane through the same path as the agent board. A pane's bell row clears as soon as the pane is viewed, whether by selecting the row, selecting the pane or focusing it, and when its view is closed or it leaves the tree. Notice rows never select. While a ray rests anywhere on the feed, rows hold still: a cleared row leaves its slot empty and new entries wait in the **+N more** count until the ray leaves the feed or XR ends, so a row never moves under the pointer, even right after you select it. The feed collects bells and notices while it is closed, so they show when it opens. Grip the feed to move it, and its × closes it.

### Performance

**Performance** adds a compact dark gauge to the left of the digital clock, turned to face you. It shows the render FPS against its target, such as `58 / 72 fps`. The target is the XR display rate, 72 Hz when the browser does not report one and 60 Hz outside XR. A dot beside it is green on pace (within 5%). Below target it turns into a triangle, amber within 25% and coral beyond, so the status does not rely on colour alone. The gauge also shows `worst (20 s)`, the longest frame in the last 20 seconds. Pauses do not count. An interval is skipped if it ends while the page or XR session is hidden or blurred, if a visibility change happened during it (a hidden tab, the Quest system menu), or if it is over 5 seconds. A real freeze of a second or two still shows. The worst-frame history clears when an XR session starts or ends. A bar chart shows each half-second's worst frame, each bar tinted by its own frame time against the budget, which is the mid-height line. The last readout is how many terminal panes are shown, meaning visible and not hidden by focus mode. It refreshes about twice a second from the same frame counter as the HUD FPS readout and does no work on other frames. Grip to move it. Its × closes it. To measure its cost, `make perf-gauge-check` (with `MUX_XR_PRIVATE_TEST=1`, `MUX_XR_BASE_URL` and `MUX_XR_TEST_ROOT`) benchmarks its update path and writes screenshots. `MUX_XR_PERF_GAUGE=1 make terminal-capacity-check` runs the capacity workload with the gauge open.

### Host load

**Host load** adds a small dark meter at 0.7 scale above and behind the performance gauge, turned to face you. It shows the Mac's 1-minute load average (`load 3.42`), the 5- and 15-minute averages with the core count, and the CPU percentage with a bar. A green dot means the host is fine. A 1-minute load above 15 (the fleet's host load rule for load-sensitive work) or CPU at 75% or more turns the dot into an amber triangle, and a load above 30 or CPU at 90% or more makes it coral. The CPU bar takes its own tone and marks 75%. It reads `/host-stats` on the dictation server (port 4242), every 5 seconds and only while the meter is open, shown and rendering, one request at a time. After the host rejects the secret it waits 65 seconds before asking again, past the server's one-minute failure window, so it never locks out Paste host. That deadline is kept in `sessionStorage` (`mux-xr.host-load-auth-retry-at`), so reloading the page or reopening the meter in the same tab does not spend another failure. A new tab starts without it. When the server refuses for load (it answered before, then closed before its challenge, or it says `rate_limited`) the meter reads **Host stats busy, retrying** and waits 15 seconds. It needs the same pairing as [host clipboard sync](HOST-SETUP.md#host-clipboard-sync). Without it, or when the server is unreachable, rejects the secret or times out (4 s), the meter reads **Unavailable** with the reason and drops the last numbers. Grip to move it. Its × closes it. `make host-load-check` renders it in headless GPU Chromium from a fake source and writes ok, warn and unavailable screenshots to `/tmp/host-load-shots`.

### Sticky note

**Sticky note** opens dictation. Review the transcript and choose **Pin as note** to place it in the workspace. Select **Read** on the compact note to page through it. Text discarded by older builds cannot be recovered from the note.

### Git & CI

**Git & CI** adds a small dark panel at 0.7 scale right of the agent board and below the analog clock, turned to face you, that follows the focused pane. It shows the repo folder name, the branch (or detached HEAD), `clean`, `dirty` or `state unknown` with ahead/behind counts against the upstream (or `no upstream`), and a CI badge for the branch's latest GitHub Actions run: green **CI passed**, coral **CI failed**, amber **CI running** or grey **CI unknown**, with the workflow name and age beside it. Dirty means staged changes or untracked files. Edits to tracked files that are not staged read as clean, because spotting them means reading file content, which runs the repo's own filters. The pane's directory comes from the shell's OSC 7 reports through the streamer, so a shell without directory reporting reads **Directory unknown**, and one whose OSC 7 report names another host reads **Remote shell**. Panes streamed from par-mux currently get a directory only if the streamer saw an OSC 7 before this page connected, and later `cd`s are not forwarded yet, so most par-mux panes read **Directory unknown** until the streamer forwards directory changes. Other states are **No pane focused**, **Checking…**, **Not a git repository** (also shown for any directory outside your home folder) and **Unavailable** with the reason, such as an unpaired host clipboard. **CI unavailable** means `gh` is missing or not signed in on the Mac, the repo has no GitHub Actions runs `gh` can see, or HEAD is detached. The widget asks the dictation server's `/repo-status` route on port 4242, which needs the same pairing secret as the host clipboard (see Host clipboard) and the server running as the LaunchAgent with `--clipboard-secret-file` and `--repo-status on` (`bun run scripts/install-dictation-service.ts --install --agent --repo-status`). Without `--repo-status on` the widget reads **Unavailable**. It queries on every focus or directory change and then every 10 seconds, only while the widget is open and the page is visible. The Mac caches the git probes for 10 seconds and `gh run list` for 60 seconds per repo, so several headsets or panes in one repo share one run. `bun run scripts/repo-status-shots.ts` renders every state with a stub status source to `/tmp/git-ci-shots`. Grip to move it. Its × closes it. If the pane has no OSC 7 directory, the widget uses the agent roster's project to find the host's checkout under `~/Repos`.

### Kanban strip

**Kanban strip** adds a dark panel at 0.7 scale centred below the HUD, turned to face you, that follows the focused pane's project on the kanban board: the first directory under `~/Repos` that holds the pane's OSC 7 directory, so a worktree inside a checkout counts as that checkout's project. It lists up to five in-progress and blocked cards with the title, a blue dot (in progress) or amber triangle (blocked), `doing` or `blocked`, the priority and the claim holder (`unclaimed`, or `(stale)` once the lease ran out). Cards tagged `approval` or titled "Approval: …" come first with a violet bar, and the header counts them. Other states are **No pane focused**, **Directory unknown**, **Not inside a ~/Repos project**, **Remote shell**, **<project> is not on the board**, **No in-progress or blocked cards** and the reason it could not ask, such as **Board feeds are off on the host** or **Kanban board unreachable from the host**. It asks the dictation server's `/kanban-strip` route a second after each focus change and then every 45 seconds while open and shown. The route is off unless the server runs with `--board-feeds on` (`bun run scripts/install-dictation-service.ts --install --agent --board-feeds`) and needs the host clipboard pairing secret. The Mac resolves the directory with `realpath`, refuses anything outside `~/Repos` or a project name that is not `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, and runs only read commands of the kanban CLI (`bun ~/Repos/kanban/cli/kanban.ts item list --project <p> --status in_progress,blocked --format json`, plus `project list` to tell an unknown project from an outage) without a shell, with a bare environment, an 8 second timeout and an output cap, one run at a time, shared for 30 seconds. Only titles, statuses, priorities, holders and the approval flag reach the headset. Grip to move it. Its × closes it. If the pane has no OSC 7 directory, the widget uses the agent roster's project to find the host's checkout under `~/Repos`.

### Host bookings

**Host bookings** adds a wide dark panel at 0.7 scale far left at eye level, turned to face you, with one row per bookable host from the kanban scheduler (`schedule resource-list`). Each row is a timeline from 30 minutes ago to 3½ hours ahead, with hour ticks and a white line at now. A live booking (booked or checked in, never cancelled or released) is a bar over its window: orange and full height for load-sensitive, blue and half height for load-tolerant. Under each track the current or next booking reads holder · project · start–end · tolerance, with `+N` for more and `free` when there are none. All times are Etc/GMT+8, such as `9:40 PM`, and the header shows the time now. It reads the dictation server's `/bookings` route every 60 seconds while open and shown, and the bars slide each minute. The route shares `--board-feeds on` with the kanban strip and needs the host clipboard pairing secret. The Mac runs `schedule resource-list`, `schedule list --status booked --limit 200` and `schedule list --status checked_in --limit 200` through the same read-only CLI runner, keeps bookings that overlap the next six hours, and never sends purposes. Without the flag it reads **Board feeds are off on the host**, and **Kanban scheduler unreachable from the host** when the CLI fails. Grip to move it. Its × closes it.

### Service health

**Service health** adds a dark panel at 0.7 scale far right just below eye level, turned to face you, with the par-obs synthetic probes: one row per service and host, a red triangle and `down`, a green dot and `up`, or a grey square and `canary` for a check configured to be down, and the time since its state last changed. Down probes come first, up to eight rows with `+N more`. The header band turns red with the count while any probe is down, green when all are up, and grey when the state is unknown. It reads the dictation server's `/service-health` route every 60 seconds while open and shown. The route is off unless the server runs with `--service-health on` (`bun run scripts/install-dictation-service.ts --install --agent --service-health`) and needs the host clipboard pairing secret. The Mac queries par-obs Grafana's Prometheus datasource proxy at the HTTPS Grafana origin set in [local host configuration](HOST-SETUP.md#local-host-configuration) with `min by (host, service) (last_over_time(par_obs_up[5m]))`, plus `par_obs_expected_down` to tell canaries apart, sending a Cloudflare Access service token in the `CF-Access-Client-Id` and `CF-Access-Client-Secret` headers. The owner creates the token file at `--service-health-env-file` (default `.local/par-obs-query.env`, gitignored) with `PAR_OBS_CF_ACCESS_CLIENT_ID=` and `PAR_OBS_CF_ACCESS_CLIENT_SECRET=` lines. Create this file before installing the service. It must be readable by its owner only (`chmod 600`): any group or other bit makes the server refuse it as not set up and log the path and mode once. It is reread on each query, never follows a redirect, and never reaches the headset or the log. par-obs keeps no change history in this query, so the streamer records each probe's state and the time it changed. Until it has seen a change, the age reads as a lower bound such as `≥5m`, counted from when it first looked. Without the flag it reads **Service health is off on the host**, without the file **par-obs token not set up on the host**, and **par-obs unreachable from the host** when the query fails. Grip to move it. Its × closes it.

### Mesh inbox

**Mesh inbox** adds a dark panel at 0.7 scale centred above the HUD, turned to face you, with the latest par-mesh messages between agents on this Mac, newest first: sender → recipient (the part before `@`), subject, `int` or `next` for the priority, and the age. Interrupt-priority rows get an orange accent bar over a tinted row. Pinching a row focuses the recipient's pane, the same way the agent board does, when the par-mux roster names exactly one agent pane for it: the only agent pane in the address's project, or the only one there whose harness starts the name (`claude-b50c` for a claude pane). Otherwise the row does nothing. It reads the dictation server's `/mesh-inbox` route every 30 seconds while open and shown. The route is off unless the server runs with `--mesh-inbox on` (`bun run scripts/install-dictation-service.ts --install --agent --mesh-inbox`) and needs the host clipboard pairing secret. The Mac runs `bun ~/.bun/bin/par-mesh history --host <host> --limit 12 --format json`, where the host is its short hostname in lowercase, without a shell, with a bare environment, an 8 second timeout and an output cap, and shares the answer for 15 seconds. Only addresses, subjects (control characters stripped, at most 80 characters), priority, time, delivery state and the sealed flag reach the headset. History has no bodies, and ack notes are never sent. Without the flag it reads **Mesh inbox is off on the host**, and **par-mesh history unreachable on the host** when the CLI fails. Grip to move it. Its × closes it.

## Pictures

The browser sidebar's **Pictures** section takes an image file (Choose image…) or an image URL (Add). A file dialog cannot open inside immersive WebXR, so files are picked on the page, before or during an XR session. In XR, pick by URL or from Recent. The sidebar scrolls when the page is short (the Quest Browser viewport), so Pictures stays reachable below the endpoint. The image is decoded, downscaled to a 2048 px long edge, re-encoded as WebP and shown in a thin dark frame 0.6 m on its long edge whose aspect matches the image. Frames turn to face you and fill five slots within about 50 degrees of straight ahead: two low beside the agent board, then three in a row above the clocks. A sixth frame starts a new layer 7 cm nearer, so two frames never share a pose, including after a reload. Grab, scale and close them like other widgets. Recenter re-slots frames you have not moved and leaves grabbed ones where you put them. XR Widgets → Add Picture spawns one empty frame reading "Add a picture" just left of the board, fully in view, with **Enter URL** and **Recent** buttons, and the next picked image fills it in place without taking a slot. The open placeholder keeps its pose through XR exit and a reload, so you can leave XR, pick on the page and come back to the filled frame. **Enter URL** opens a URL field over the virtual keyboard (Keyborb included): type it, or use **Paste** (Quest clipboard) or **Paste host** (the Mac clipboard), then **Load** or Enter. A physical keyboard types into the field too, and its keys never reach the shell while the field is open. It goes through the same loader, queue and notices as the page, but while the panel is open a failure reason shows in the panel itself rather than the HUD.

A second Load while one is loading only shows "Loading…". **Recent** opens a 3 x 2 gallery of earlier picks with Prev/Next, a × per tile to remove it from Recent, and a tap on a tile to put it in the frame. A filled frame has a **Change** button in its bottom-left corner that offers the same two choices and replaces that frame in place. Recent keeps the last 12 picks (48 MB, 256 px WebP thumbnails included) in its own IndexedDB database, separate from the live frames, evicts the least recently used (with a notice once per page session), survives reloads and keeps a picture after its frame closes. Without IndexedDB the gallery reads "Recent pictures need browser storage" and URL entry still works.

URLs are fetched with CORS first. A host that refuses CORS or cannot be reached shows "Image blocked by CORS: <host>" on the HUD and the page, unless the [optional picture proxy](HOST-SETUP.md#picture-proxy) is on, in which case the Mac fetches the image for you.

HEIC/HEIF photos (iPhone and most Android cameras) are decoded too: the browser has no HEIF decoder, so the page loads libheif ([libheif-js](https://github.com/catdad-experiments/libheif-js) 1.23.5, LGPL-3.0, shipped as its own unmodified `libheif-*.wasm` asset) in a Worker only when a HEIF is opened, decodes the primary image with its rotation applied, and terminates the Worker afterwards. A 24 MP iPhone photo takes about 2.5 s on Quest 3, off the render thread. The HEIF size limit (50 megapixels, below the 64 MP browser limit because the wasm decode holds several full-size copies) is read from the container before any tiles are decoded, and only files carrying an HEVC brand go to libheif. The primary image is used for the flat view. Supported stereo pairs can also be shown through the frame’s 3D options.

Bad files, non-images and images over 40 MB, 16384 px or 64 megapixels show their own notice (oversized dimensions are read from the file header before decoding, a file over 8 MB whose header gives no size is refused, and a URL body is read with the same byte cap). A URL that takes over 20 s times out, and an `http:` URL on an `https:` page shows "Mixed content blocked: use an https URL". Picks run one at a time, and Enter or Add do nothing while one is loading. A failed load never creates a frame.

Picked images live in IndexedDB, capped at 8 frames and 32 MB. The oldest is evicted with a notice. The scene holds the same 8-frame cap when IndexedDB is unavailable. Their poses are saved in the widget pose store, and frames restore on reload. Closing a frame deletes the frame image and retains its Recent entry.

Open a frame’s **3D** controls to switch between Inward and Pop out. A supported stereo pair can use its captured Stereo source. Depth map rendering requires the optional [picture depth route](HOST-SETUP.md#optional-host-routes), with controls for strength and edge treatment.

## Frontend updates

Production builds include a content fingerprint in the page and a same-origin `version.json` manifest. The frontend checks immediately and every 30 seconds with a five-second request timeout and cache bypass. A changed build shows a compact **Update available / Reload** notice in the browser and an **Update: Reload** action on the XR HUD. On the desktop main page, detected updates reload automatically. In immersive XR, updates wait for an explicit reload. A cyan indicator appears on the watch face when a newer build is available, and the watch menu shows **Reload update**. Reload exits the immersive session first, then loads a fresh page with a cache-busting URL. Terminal processes remain running, and saved device preferences and commands remain in local storage.

The identifier covers the bundled application and public assets, so a font or environment asset update also triggers the notice. Development uses Vite's existing reload behavior rather than production polling.

See the [radial design notes](../design/radial-menus.md) for the menu and glass design.
