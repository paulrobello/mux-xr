# Testing Mux XR

Run these commands from the repository root. Install the pinned dependencies with `bun install --frozen-lockfile`. The full local gate also requires `uv` and `gitleaks` on PATH.

## Local gates

- `make checkall` runs the protocol check, Biome, TypeScript, unit tests, and the production build.
- `make checkall-ci` adds the bundle size budget, asset validation, secret scanning, and the dependency audit.

### Bundle size budget

`make bundle-budget` compares the JavaScript chunks emitted into `dist/assets` with the limits in `bundle-budget.json`. It bounds the entry chunk, each named vendor chunk, the largest lazy chunk, and the total JS, in raw minified bytes (not gzip), because Quest parse and compile cost follows raw size. To raise a limit, change `bundle-budget.json` in the same commit as the code that needs it, with the reason in the commit message. Measured sizes live in `docs/performance/`.

There are no tracked CI workflows. `make checkall-ci` is the full local gate. The browser and live-streamer checks below run separately.

### Git hooks

Install both hooks once in every clone and every worktree with `pre-commit install --hook-type pre-commit --hook-type pre-push`. The pre-commit stage scans staged files for secrets and runs the fast gate, which documentation-only commits skip. The pre-push stage runs `make checkall-ci`.

The hooks are advisory. `git commit --no-verify` and `git push --no-verify` skip them, and a fresh clone or worktree has none until the install command runs. They narrow the gap left by having no remote CI without closing it.

## Property tests

The trust boundaries have property-based tests in `tests/property/`: the terminal frame decoder, the paste sanitizer, the paired-route handshake, and the settings and pose validators. They run with the rest of the unit tests (`bun run test tests/property` selects just the property files) through the same Vitest projects, with the paired-route file in the Node project like every other `src/server` test.

Every property runs 200 generated cases (`numRuns: 200`) with one seed for the whole file: `FC_SEED` when set, otherwise the constant 20261116. A gate failure prints the seed and a shrunk counterexample; rerun it with `FC_SEED=<seed from the log> bun run test tests/property` to reproduce the exact run. The oversize-frame bound property runs 15 cases because each case inflates a real 9 MiB stream.

When a property finds a counterexample in shipped code, the fix adds a named example test covering that exact input, so the regression keeps a permanent, readable witness. Keep the property as the boundary guard.

## Browser fixtures

Install the Chromium revision pinned by Playwright with `bunx playwright install chromium --no-shell --no-remove`. Run `make e2e` against a local app. Set `MUX_XR_BASE_URL` if the app is on a different port. The suite uses synthetic protocol fixtures across desktop, tablet, and mobile viewports.

Browser tests use hardware Chromium headless on supported hosts. Book the host before load-sensitive work and record the renderer and load for performance results.

## Check targets

Each check target runs `bun run scripts/run-check.ts <name>`. Every target, its environment requirements and its row in the table below are declared once in `scripts/checks/manifest.ts`; the Makefile rules and this table are checked against that manifest by `tests/check-manifest.test.ts`, and the runner refuses to start a check whose required variables are unset, naming every one that is missing. Browser targets use GPU Chromium and reject SwiftShader. A target that lists `MUX_XR_PRIVATE_TEST` refuses to run without `MUX_XR_PRIVATE_TEST=1`, because it sends input, resizes or creates panes, or serves a copy of the build. Point it at a loopback fixture you own. `MUX_XR_TEST_ROOT` is an owned temporary directory that holds a copy of `dist`. A target with no `MUX_XR_BASE_URL` in its required column serves that root itself on a loopback port.

### Private real-streamer checks

Use an isolated daemon socket, streamer, and test panes. The prepared LAN preview uses the shared default daemon. Restrict live delivery verification to static frontend files and normal application startup. `make real-app-check` issues two harmless marker commands, so use isolated test panes. The targets that create panes, resize panes or report agent state refuse to run without `MUX_XR_PRIVATE_TEST=1`.

Bring a private pair up from clean like this (verified 2026-11-17 with `make real-app-check`; re-verified 2026-11-18 on core 0.83.0):

1. Inside a par-mux pane (`PAR_MUX_ENV` set), export `PAR_MUX_ALLOW_NESTED=1` first; the daemon start refuses to run nested without it. On a par-mux 0.83 daemon also export `PAR_MUX_NO_APP_WRAPPER=1`, or `start` hands off to `/Applications/Par-mux.app` and the handoff can die between tool calls.
2. `par-mux --socket /tmp/<scratch>.sock start --no-attach --state-dir <scratch>/state` starts the private daemon on its own socket. The 0.83 daemon refuses to start when another daemon already serves the platform state file, so pin the scratch state dir. A `--no-attach` daemon exits once its tree has been empty for five seconds, so create the session (step 3) immediately after start or the daemon dies under the check.
3. `par-mux --socket <scratch>.sock --cmd "new-session -d -s <name>"` must run before any `new-window`: a fresh daemon has no sessions, and `new-window` refuses with "no sessions exist" until one exists.
4. Create the panes the check needs with `new-window` (two shell panes for `real-app-check`, whose marker commands need a shell to execute; `agent-roster-app-check` needs its panes running `claude` or `codex` processes so the daemon keeps the claims, per its table row).
5. Start the streamer on a loopback port with an owned copy of `dist`: `.local/bin/streamer-candidate --host 127.0.0.1 --port 4241 --enable-http --web-root <scratch>/dist --mux-socket <scratch>.sock --allow-unauthenticated`. The default `MUX_XR_BASE_URL` of `http://127.0.0.1:4241` then needs no override. `agent-roster-app-check` additionally takes `MUX_XR_MUX_SOCKET=<scratch>.sock`.
6. Run the check with `MUX_XR_PRIVATE_TEST=1 make <target>`, then tear down: stop the streamer, `par-mux --socket <scratch>.sock stop`, and delete the scratch tree.

## Physical Quest checks

Browser and simulated XR checks establish software behavior. Verify real controller and hand interactions, text readability, passthrough, microphone permissions, and comfort on the headset. Capacity and frame pacing require a measured headset workload. The owner reported that the controller build worked well on Quest 3. Hand input still requires physical acceptance.
